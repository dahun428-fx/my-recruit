# GS네오텍 자기소개서 (GS네오텍 입사지원서 양식용 — 소유자 작성본, 2026-09-14)

> 소유자가 직접 작성해 전달한 문안. 볼드(**)는 2026-09-14 소유자 요청으로 C-03 강조 배분(주어+결과 절, 줄 첫머리 금지)에 따라 표시만 추가 — 문구 불변. 문구 무수정 원칙(소유자 확정본). 문단 구분은 전달본의 의미 단위로 나눔.

## ① 본인의 핵심역량(차별화된 강점 등)

저는 **화면, API, DB, 배포를 한 흐름으로 다루며 운영 중인 서비스를 개선해 온 풀스택 개발자**입니다. 여기에 **Claude Code와 Codex를 활용한 개발·검증 자동화 경험**을 더한 것이 저의 강점입니다.

비즈36.5 건강검진 플랫폼에서는 Java·Spring Boot와 MyBatis·MySQL로 건강기록 기능을 개발했습니다. 기존 기능에 영향을 주지 않도록 데이터 구조를 설계하고, **주요 조회 조건에 맞춰 인덱스를 적용한 뒤 실행 계획으로 성능을 확인**했습니다. 화면에 필요한 데이터는 Node.js BFF에서 가공하도록 구성하고 주요 API를 구현했습니다. 또한 **기존 jQuery 화면과 React 화면이 함께 동작하도록 전환 구조를 설계**하고, 담당 화면을 단계적으로 React로 전환했습니다.

개발 이후의 배포와 운영도 직접 맡았습니다. 수동 배포를 Jenkins 파이프라인으로 바꾸고 Docker Blue-Green 방식을 적용해 **배포 시간을 10분에서 2분으로 줄였**습니다. AWS EC2·S3 환경에서 서비스를 운영하며 Linux 로그 확인, 서비스와 컨테이너 재기동, 환경변수와 Nginx 설정을 수행했습니다.

최근에는 사내 문서 검색과 테스트 실행을 위한 **MCP 서버 2종을 개발·개선해 Claude Code와 Codex에 연동**했습니다. AI가 작성한 코드는 기존 코드와의 연결 관계를 살펴보고 **단위·통합·E2E 테스트를 거쳐 반영**했습니다. 기능 구현에 그치지 않고 성능과 배포, 운영까지 살피면서 반복되는 개발 작업은 AI와 자동화로 줄일 수 있습니다.

## ② 성격의 장단점 및 보완 노력

제 장점은 모호한 요구사항을 그대로 구현하지 않고 **실제 업무 흐름과 예외 상황을 확인해 기준을 세우는 점**입니다. 건강관리실 동의서 기능을 기획할 때 보건 담당자·기획·운영 부서와 기존 업무를 함께 살폈습니다. 동의서 발송과 회수, 대리 등록, 철회, 담당자별 권한처럼 실제 업무에서 발생하는 상황을 확인한 뒤 시스템 요구사항으로 정리했습니다. 검진 진행현황 기능도 현장 보건관리자의 의견을 받아 **수검 판정 기준과 기능 범위를 구체화**했습니다.

반면 확인 범위를 넓게 잡다 보면 검토에 예상보다 많은 시간이 들기도 합니다. 이를 보완하기 위해 **서비스에 미치는 영향과 발생 빈도를 기준으로 확인 순서를 정하고**, 반복되는 검증은 자동화하고 있습니다. 챗봇 응답과 UI를 확인하는 도구를 직접 만들어 배포 전에 실행하도록 연결했고, **반복 QA 시간을 3시간에서 30분으로 줄였**습니다. 확인 기준은 문서와 테스트로 남겨 팀원도 같은 방식으로 검증할 수 있도록 했습니다. 꼼꼼함은 유지하되 모든 것을 사람의 반복 확인에 의존하지 않는 방식으로 속도와 품질을 함께 관리하고 있습니다.

## ③ 열정을 다해 성공적으로 마친 경험 (업무/프로젝트/활동)

대웅제약 AI추진팀에서 AI 건강검진 챗봇인 **AI코치를 PoC에서 실서비스로 전환한 경험**이 가장 기억에 남습니다. 개발자 5명이 10주 안에 서비스를 완성해야 했지만, 당시에는 형식이 일정하지 않은 LLM 응답을 화면에서 어떻게 처리할지 명확한 기준이 없었습니다. 스트리밍이 중간에 끊기거나 서버와 LLM에서 오류가 발생하는 상황도 함께 해결해야 했습니다.

저는 Python 기반 LLM API 연동 릴레이 서버와 API 구축에 참여하고, 프롬프트·컨텍스트 구성 및 응답 검증 도구를 담당했습니다. 구현에 앞서 AI 개발자와 응답 형식, 스트리밍 처리 방식, 오류 발생 시 동작을 정리했습니다. **오류를 네 가지 유형으로 구분해 복구 흐름을 설계**하고, 화면 출력 과정에는 XSS 필터링을 적용했습니다. 개발 중에는 실제 질문을 바탕으로 발화 400건을 반복 검증하며 발견한 문제를 프롬프트와 화면 처리 로직에 반영했습니다.

팀은 **10주 만에 AI코치를 임직원 3,493명이 사용하는 실서비스로 전환**했습니다. 발화 400건을 검증한 결과 **화면 출력 오류 없이 정상 동작**하는 것을 확인했습니다. 출시 일정만 맞추는 데 그치지 않고, 다양한 응답과 오류 상황에서도 사용자가 안정적으로 서비스를 이용할 수 있는 기준을 마련했다는 점에서 의미가 컸습니다. 이 경험을 통해 새로운 기술을 빠르게 적용하는 것만큼 예외 처리와 검증 방법을 함께 설계하는 일이 중요하다는 것을 배웠습니다.

## ④ 지원동기 및 입사 후 포부

SI 프로젝트와 자사 플랫폼 운영을 모두 경험하면서 기능을 구현하는 것만큼 **기존 코드와 데이터 구조를 빠르게 파악하고 안정적으로 배포하는 일**이 중요하다는 것을 배웠습니다. 다양한 고객 환경에서 IT 서비스와 솔루션을 제공하는 GS네오텍에서라면 제가 쌓아 온 풀스택 개발·운영 경험을 활용하면서 **더 다양한 플랫폼 문제를 해결**할 수 있다고 생각해 지원했습니다.

내담씨앤씨에서는 삼성물산 건설부문과 한국미스미 프로젝트를 수행하며 고객마다 다른 요구사항과 기술 환경에 맞춰 개발했습니다. 이후 대웅제약과 다나아데이터에서는 건강검진 플랫폼과 AI 챗봇을 지속적으로 개발·운영하며 **데이터 모델과 API, 화면 구현부터 성능 개선, 배포 자동화와 오류 대응까지 담당**했습니다. 최근에는 **Claude Code·Codex와 MCP를 실무에 적용해 개발과 검증에 걸리는 시간을 줄였**습니다. 이러한 경험은 GS네오텍의 운영 중인 플랫폼에 빠르게 적응하고 필요한 기능을 안정적으로 구현하는 데 도움이 될 것이라고 생각합니다.

입사 후에는 담당 플랫폼의 코드 구조와 데이터 흐름, 배포 환경을 먼저 파악하겠습니다. 운영 중 발생하는 오류와 반복 요청을 처리하며 서비스에 대한 이해를 높이겠습니다. 조회가 느린 기능은 **쿼리와 인덱스, API 응답, 화면 렌더링을 나눠 원인을 찾고**, 신규 기능은 기존 데이터와 서비스에 미치는 영향을 확인한 뒤 테스트를 거쳐 배포하겠습니다.

이후에는 반복되는 개발·검증 작업을 자동화하고, Claude Code와 Codex를 팀이 안전하게 활용할 수 있도록 프로젝트에 맞는 검증 기준을 정리하겠습니다. 장기적으로는 클라우드와 대용량 데이터 처리 역량을 넓혀 **기능 개발, 성능 개선, 배포와 운영 자동화까지 책임질 수 있는 플랫폼 개발자**로 성장하겠습니다.
