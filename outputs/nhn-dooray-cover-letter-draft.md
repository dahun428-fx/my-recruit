# 정다훈 자기소개서 (NHN Dooray! 협업서비스개발실 · 프론트엔드 개발자 지원용)

## 여러 사용자가 함께 쓰는 서비스의 프론트엔드를 안정적으로 운영하는 개발자

저는 React·Vue 3·TypeScript 기반 SPA를 개발·운영해 온 6년차 프론트엔드 중심 개발자입니다. 화면 구현에 그치지 않고, 프론트엔드 변경이 서비스 전반에 미치는 영향을 파악하기 위해 API 응답 정책, 오류 대응, 데이터 흐름, 배포 검증까지 함께 살펴 제품 완성도를 높이는 방식으로 일해 왔습니다. 응용SW엔지니어링 과정을 이수하고 정보처리기사를 취득한 뒤 실무에서 전공에 준하는 개발 역량을 쌓았으며, B2B 플랫폼처럼 여러 고객사와 다수 사용자가 동시에 쓰는 서비스의 품질과 운영 안정성에 특히 강점을 두어 왔습니다.

협업 서비스는 메일·프로젝트·메신저·캘린더처럼 여러 기능이 유기적으로 맞물려 돌아가고, 한 번의 배포가 많은 사용자에게 곧바로 영향을 줍니다. 공공·교육·민간 등 다양한 고객사가 함께 쓰는 Dooray!라면 권한·정책 관리와 배포 안정성이 특히 중요하다고 생각합니다. 저는 다수 고객사와 사용자가 함께 쓰는 B2B 서비스에서 실시간 응답 처리, 권한·메뉴 정책, 고객사별 배포 대응, 재사용 가능한 프론트엔드 기반을 다뤄 왔고, 이 경험이 협업서비스개발실이 중시하는 안정적인 서비스 운영과 맞닿아 있다고 판단해 지원했습니다.

## 디자인시스템과 공통 컴포넌트로 반복 개발을 줄이다

대웅제약 AI추진팀에서는 서비스와 고객사가 늘면서 화면·문구·테마·기능 노출 조건이 제각각 달라지는 문제가 있었습니다. 고객사마다 서비스를 개별 개발하면 구축 기간과 품질 편차가 커진다고 판단해, 공통 화면과 컴포넌트를 Base-Theme으로 분리하고 고객사별 차이를 Config-Driven UI로 관리하는 구조를 설계했습니다. Storybook을 중심으로 컴포넌트 상태별 개발·검증 절차를 세워 재사용 가능한 공통 컴포넌트 자산을 확보했습니다.

그 결과 반복 컴포넌트의 개발·검증 시간을 90분에서 15분으로 단축했고, 신규 AI 챗봇 구축 기간을 기존 10주에서 약 2주 수준으로 줄일 수 있는 기반을 마련했습니다. 디자인시스템과 신규 컴포넌트를 개발·유지보수하는 Dooray! 협업 서비스에서도, 반복 개발 공수를 줄이고 일관된 사용자 경험을 지키는 데 기여할 수 있습니다.

## 고객사별 배포와 점진적 전환으로 안정 운영을 지키다

외주 중심으로 운영되던 B2B 임직원 건강 플랫폼을 내부에서 개발·운영할 수 있는 구조로 전환한 경험이 있습니다. 기존 jQuery·Thymeleaf 화면과 Spring Boot·MySQL 구조가 기능별로 결합돼 변경 영향 범위를 파악하기 어려웠고, 고객사별 CI·메뉴·기능 노출 정책도 일관되지 않았습니다.

화면 요청부터 Controller·Service·Query·DB 조회·화면 출력까지 데이터 흐름과 의존 관계를 정리한 뒤, 기존 운영에 영향을 주지 않도록 jQuery·Thymeleaf와 React가 화면 단위로 공존하는 점진적 전환 구조를 적용했습니다. 사용자 권한·메뉴·브랜딩·데이터 출력 정책은 공통 기준으로 정리해 고객사별 배포 대응 구조를 확보했습니다. 그 결과 서비스를 중단하지 않고 108개 페이지·82개 화면 규모의 전환을 9주 안에 수행했으며, 고객사별 기능 노출 변경을 1주 내에 대응할 수 있는 운영 구조를 만들었습니다. 그룹웨어나 설치형 제품을 직접 개발·운영한 경험은 아니지만, 다수 고객사가 각기 다른 정책으로 함께 쓰는 서비스를 무중단으로 유지보수하고 배포해 온 경험은 다양한 고객사에 서비스를 제공하는 Dooray!의 안정 운영에도 활용할 수 있다고 생각합니다.

## AI 기능을 실서비스에 안정적으로 도입하다

목업 수준의 AI 건강검진 챗봇을 실사용 가능한 서비스로 고도화하는 일을 맡았습니다. 초기 챗봇은 LLM 답변이 모두 생성된 뒤 화면에 출력돼 체감 대기 시간이 길었고, Markdown·표·링크 같은 비정형 응답을 안정적으로 처리할 구조가 없었습니다.

AI 개발자와 API 응답 형식·스트리밍 방식·오류 정책을 조율하고, SSE 기반 실시간 렌더링과 답변 중지·재시도·오류 상태 처리를 구현했습니다. Markdown 전용 렌더링 계층을 만들어 표·목록·링크·차트를 React 컴포넌트로 변환하고, XSS 필터링과 함께 LLM 응답 오류·타임아웃 시 대체 UI로 처리하는 가드레일을 적용해 예측하기 어려운 응답도 안전하게 출력되도록 했습니다. 그 결과 3,493명을 대상으로 PoC를 수행하며 답변 출력 시간을 10초에서 4초로 단축했고, 초기 진입 시간을 30초에서 6초로 줄여 Lighthouse 91점을 확보했습니다. 400건 발화 검증 기준 답변 화면 정상 출력률 100%를 달성했습니다. 메일·프로젝트 등 협업 흐름에 AI 기능을 도입할 때에도, 비정형 AI 응답을 안정적인 화면 경험으로 전환해 온 경험으로 기여하겠습니다.

## 품질 자동화와 공유로 팀과 함께 성장하다

서비스가 늘면서 수동 QA와 배포 전후 확인이 병목이 되자, Playwright 기반으로 주요 사용자 흐름과 E2E 회귀 시나리오 600여 건을 자동화하고, 타입·테스트·빌드 확인과 배포 전후 검증을 하나의 품질 흐름으로 연결했습니다. Jenkins와 GitLab CI/CD 기반 빌드·검증·배포 파이프라인도 함께 정비했습니다. 이 자동화로 반복 QA 시간을 3시간에서 1시간으로 줄였습니다. 또한 개발 세미나 12회와 기술 문서 48건, FE 개발 기준 문서화를 통해 배운 것을 팀에 공유하는 문화를 만들었습니다.

이 과정에서 저는 역할과 직군이 달라도 근거와 영향 범위를 기준으로 논의하며, 기획·디자인·백엔드·AI 개발·운영 조직과 응답 정책·배포 프로세스·오류 대응 기준을 함께 맞춰 왔습니다. 수평적으로 소통하고 학습과 공유를 중시하는 협업서비스개발실의 방향이, 배운 것을 문서와 세미나로 나눠 온 제 방식과 잘 맞는다고 생각합니다. Dooray!가 글로벌 통합 SaaS로 성장하는 과정에서, 여러 사용자가 매일 신뢰하고 쓰는 협업 서비스의 프론트엔드 품질과 운영 안정성을 함께 끌어올리고 싶습니다.
