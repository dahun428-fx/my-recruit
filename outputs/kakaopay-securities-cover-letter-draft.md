# 정다훈 자기소개서 (카카오페이증권 · MTS 프론트엔드 지원용)

## 실시간성과 안정성이 함께 요구되는 웹뷰 서비스를 만들어 온 프론트엔드 개발자

저는 5년 9개월간 React·Next.js·TypeScript 기반의 웹뷰 서비스를 개발·운영해 온 프론트엔드 개발자입니다. 짧지 않은 기간 동안 레거시의 Next.js 전환, 목업 수준 AI 서비스의 실서비스 제품화, 테스트·배포 자동화, LLM 도구의 팀 도입까지 서비스의 한 생애주기를 여러 번 직접 돌려봤습니다. 화면 구현에 그치지 않고 API 응답 정책·오류 처리·배포 검증까지 함께 설계해 제품 완성도를 책임지는 방식으로 일해 왔습니다.

카카오페이증권이 소액·저경험 사용자도 다양한 금융 상품에 쉽게 접근하도록 새로운 투자 문화를 만든다는 점에 지원 동기를 두었습니다. MTS는 실시간 시세와 체결처럼 지연이 곧 신뢰 손실이 되는 화면을, 다양한 사용자가 웹뷰 환경에서 매일 쓰는 서비스입니다. 저는 실시간 응답을 안정적으로 렌더링하고, 웹뷰 환경의 호환성을 검증하며, 배포 후에도 지표로 문제를 잡아내는 일을 해 왔고, 이 경험이 MTS 프론트엔드가 중시하는 실시간성과 안정성에 맞닿아 있다고 판단했습니다.

## 웹뷰 환경의 실시간 응답을 안정적으로 다루다

대웅제약 AI추진팀에서 목업 수준의 AI 건강검진 챗봇을 실사용 가능한 서비스로 고도화했습니다. 초기 챗봇은 LLM 답변이 모두 생성된 뒤 한 번에 출력돼 체감 대기 시간이 길었고, 표·링크·차트 같은 비정형 응답을 안정적으로 처리할 구조가 없었습니다.

AI 개발자와 API 응답 형식·스트리밍 방식·오류 정책을 조율하고, SSE 기반 실시간 렌더링과 답변 중지·재시도·오류 상태 처리를 구현했습니다. Markdown 전용 렌더링 계층을 만들어 표·목록·링크·차트를 React 컴포넌트로 변환하고, XSS 필터링과 LLM 응답 오류·타임아웃 시 대체 UI로 처리하는 가드레일을 적용했습니다. 그 결과 3,493명을 대상으로 PoC를 수행하며 답변 출력 시간을 10초에서 4초로, 초기 진입 시간을 30초에서 6초로 단축했고, 400건 발화 검증 기준 답변 화면 정상 출력률 100%를 확보했습니다. 이 챗봇을 포함한 대웅제약 서비스는 웹뷰 앱으로 제공됐고, 임직원 건강 플랫폼을 웹뷰로 운영하며 iOS·Android 호환성 검증 기준을 세웠습니다.

MTS의 핵심인 실시간 시세는 양방향 통신인 웹소켓을 씁니다. 저는 실무에서는 SSE 단방향 스트리밍으로 실시간 응답을 다뤘고, 웹소켓 기반 양방향 통신은 사이드 프로젝트로 직접 구현하며 연결 유지·재연결·메시지 상태 동기화의 차이를 학습했습니다. 실시간 응답을 중지·재시도·오류 상태와 함께 UI로 동기화해 본 경험이 있어, 실무에서 웹소켓 기반 시세 화면을 다루는 데 빠르게 적응할 수 있다고 생각합니다.

## 테스트와 지표로 서비스의 안정성을 지키다

금융 서비스는 한 번의 배포가 곧바로 사용자 자산 화면에 영향을 주기 때문에, 저는 서비스 안정성을 사람 확인이 아니라 테스트와 지표로 지키는 방식을 만들어 왔습니다. 서비스와 공통 컴포넌트가 늘면서 수동 QA가 병목이 되자, Playwright로 주요 사용자 흐름과 E2E 회귀 시나리오 600여 건을, Jest로 단위 테스트를 자동화했습니다. Jenkins·GitLab CI/CD 빌드·검증·배포 파이프라인도 함께 정비해, 반복 QA 시간을 3시간에서 1시간으로, 배포 리드타임을 10분에서 2분으로 줄이고 테스트 커버리지 98% 수준을 확보했습니다(내부 측정 기준).

배포 이후에는 Datadog·GA4·PostHog·Lighthouse로 성능·오류·사용자 행동 지표를 확인하고, 이를 근거로 렌더링 병목과 네트워크 비용을 개선했습니다. HTTP/2 전환으로 네트워크 비용을 1,200KB에서 900KB로 줄인 것도 지표를 먼저 보고 판단한 결과였습니다. 카카오페이증권이 쓰는 OpenTelemetry·Grafana·Sentry를 실무에서 다뤄본 적은 없지만, 관측 지표로 문제를 특정하고 개선까지 잇는 방식은 도구가 달라도 같으므로 빠르게 익힐 수 있습니다.

## LLM 도구를 실무와 팀에 정착시키다

AI코치·비즈36.5·바이오에이지를 운영하며 Cursor·Claude 같은 LLM 기반 AI 도구를 실무 개발에 적용했습니다. 다만 AI가 생성한 코드는 품질·보안·일관성이 제각각이라, 팀이 같은 기준으로 쓰려면 검증 기준이 필요하다고 판단했습니다. 그래서 AI 생성 코드의 컨텍스트 관리·금지 패턴·보안 위험·검증 절차를 FE AX SOP로 문서화하고, 개발 세미나 12회와 기술 문서 48건으로 팀에 공유했습니다.

혼자 빠르게 쓰는 데 그치지 않고 팀의 도입 기준을 세우고 반복 컴포넌트 개발 시간을 90분에서 15분으로 줄인 이 경험이, 조직 내 서비스를 함께 고도화하고 잠재적 기술 리스크를 미리 잡아 구조를 개선하는 MTS 프론트엔드의 기술 리딩 역할과 잘 맞는다고 생각합니다. 정식 팀 리드 직함을 맡은 적은 없지만, 기준을 문서로 세우고 세미나로 나누며 팀의 개발 방식을 바꿔 온 방식으로 기여하겠습니다.

## 부족한 부분을 정직하게 인정하며

증권·트레이딩 도메인을 직접 개발한 경험은 아직 없습니다. 이 부분은 짧은 시간에 메울 수 없다는 것을 알고 있고, 그래서 도메인 지식은 빠르게 배우겠다는 말 대신 제가 이미 가진 강점으로 답하려 합니다. 저는 실시간 응답을 안정적으로 렌더링하고, 여러 고객사·사용자가 쓰는 웹뷰 서비스를 무중단으로 유지보수·배포하며, 테스트와 지표로 품질을 지켜 온 경험이 있습니다. 이 역량은 도메인이 헬스케어에서 금융으로 바뀌어도 그대로 쓰입니다.

경력 연수가 채용 기준에 다소 못 미친다는 점도 알고 있습니다. 다만 저는 그 기간 안에 레거시 전환·AI 제품화·테스트 자동화·LLM 도구 팀 도입을 직접 설계하고 실행하며 밀도 있게 성장해 왔습니다. 카카오페이증권의 MTS에서, 사용자 입장에서 사용성을 고민하고 기술 리스크를 미리 잡는 프론트엔드 개발자로 함께 일하고 싶습니다.
