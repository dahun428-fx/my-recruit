# Base Resume 디자인 재구성 제안

검토 대상: `DESIGN.md`, `outputs/base-resume.{pdf,html,css}`

## 결론

추천 방향은 샘플 A `Editorial Focus`다. 현재 이력서의 신뢰감과 인쇄 안정성을
유지하면서, 첫 페이지에서 **정체성 → 요약 → 증거**가 순서대로 읽힌다.
사진을 없애거나 표 형태로 과도하게 구조화하지 않아 국내 채용 문서에도
무리 없이 적용할 수 있다.

## 현재 디자인에서 유지할 것

- A4 단일 컬럼과 18~19mm 여백
- 흰 종이, 먹색 본문, 제한적인 딥 네이비
- 사각형과 얇은 수평선 중심의 문서 언어
- 경력기술서의 `21mm 라벨 + 본문` 구조
- 하단 섹션명과 페이지 번호
- Noto Sans KR, `keep-all`, 숫자의 tabular 정렬

## 실제 PDF에서 보인 문제

1. 첫 페이지의 제목, 프로필 박스, 요약, 네 개 핵심 성과가 모두 비슷한
   강도로 보여 첫 시선의 도착점이 분산된다.
2. 본문이 대체로 8.1~8.3pt라 정보량은 잘 들어가지만, 화면 미리보기에서는
   성과 문장이 한 덩어리로 보인다. 글자를 더 줄이기보다 핵심 성과를
   `분류명 - 성과명 - 수치`의 세 단계로 나누는 편이 낫다.
3. 2페이지와 9페이지는 큰 하단 여백이 남고, 경력기술서 페이지는 상대적으로
   조밀하다. 스타일보다 페이지 분배 문제이며, 최종안에서는 8페이지 전후로
   재조립하는 것이 자연스럽다.
4. 현재 프로필의 외곽 박스는 정돈감은 있지만 시각적으로 한 덩어리가 커서
   제목과 경쟁한다.
5. 기술 페이지의 구조는 좋지만 스택명, 설명, 구분선의 반복이 모두 같은
   패턴이라 중요 기술과 보조 기술의 차이가 약하다.

## 세 가지 샘플

### A. Editorial Focus - 추천

- 사진은 작게 유지하고 프로필 외곽 박스를 제거한다.
- 제목 아래 이름과 직무를 붙여 인물 정보가 제목에서 끊기지 않게 한다.
- 섹션 번호와 영어 소제목은 작은 네이비 텍스트로만 사용한다.
- 핵심 성과를 `AI Product`, `Platform`, `Performance`, `Team System`으로
  분류해 한눈에 역할 범위를 읽게 한다.
- 예상 효과: 인사담당자는 10초 안에 정체성과 대표 수치를 읽고,
  기술담당자는 그 아래 근거로 자연스럽게 이동한다.

### B. Structured Ledger

- 사진을 제거하고 이름, 연락처, 핵심 증거를 표처럼 정렬한다.
- 각 성과의 오른쪽에 대표 수치를 따로 둔다.
- ATS와 화면 열람에 가장 강하고, 핀테크·플랫폼·외국계 지원에 잘 맞는다.
- 단점: 국내 전통 기업에는 다소 차갑고 컨설팅 문서처럼 보일 수 있다.

### C. Korean Classic

- 현재안의 사진과 보수적인 정보 구조를 유지한다.
- 프로필 박스를 얇은 구분선 구조로 바꾸고 제목 크기를 조금 낮춘다.
- 요약과 성과에 동일한 27mm 좌측 라벨을 적용해 페이지 전체 리듬을 맞춘다.
- 가장 안전하지만 A보다 개인의 포지셔닝이 덜 선명하다.

## 최종안에 권하는 수치

- 페이지 여백: 상 17~18mm, 좌우 18~19mm, 하 17mm
- 첫 페이지 제목: 19~20pt / 1.28
- 섹션 제목: 10.5~11pt
- 본문: 8.4~8.6pt / 1.65~1.72
- 성과 설명: 7.9~8.1pt / 1.55~1.62
- 프로필 사진: 25~27mm × 31~34mm
- 네이비 사용: 섹션 번호, 분류명, 링크만
- 한 페이지의 강한 구분선: 최대 2개

## 적용 순서

1. 샘플 A를 기준으로 첫 페이지를 먼저 확정한다.
2. 경력 페이지는 현 구조를 유지하되 하단 여백을 다음 페이지 콘텐츠와
   재분배한다.
3. 기술 페이지는 각 묶음의 대표 스택만 진하게 하고 설명은 한 단계 낮춘다.
4. 경력기술서는 현재 `라벨 + 본문` 구조를 유지하면서 프로젝트 제목과
   결과 수치 사이의 대비만 높인다.
5. Additional Information은 경력 또는 기술 페이지의 남는 공간과 합쳐
   전체를 8페이지 전후로 줄이는 안을 우선 검토한다.
6. 최종 렌더 후 고정 높이와 자동 높이의 페이지 수를 비교해 잘림을 검증한다.
