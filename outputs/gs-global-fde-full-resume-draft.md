### 1) 팀 AX 전환 리드 — AI 활용 개발 표준과 검증 체계 구축

- 기간: 2026.01 ~ 2026.06
- [주요 업무]: 팀의 AI 활용 개발 방식 전반을 설계·리드 — AI 생성 코드 검증 체계 구축, 프론트엔드 AI 활용 개발 표준 단독 설계, 품질·운영 자동화와 팀 지식 자산화 주도

#### 문제

AI 코딩 에이전트를 도입하면 병목은 코드를 만드는 속도가 아니라 만들어진
코드를 무엇으로 믿을지로 옮겨갑니다. 도입은 됐지만 팀원마다 활용 방식이
달랐고, AI가 만든 코드를 누가 어떤 기준으로 신뢰할 것인지가 정의돼 있지
않았습니다. 그 위에 수동 발화 테스트·반복 UI 개발·배포 전후 확인·운영 지표
조회의 병목이 겹쳐 있었습니다.

#### 주요 실행

- **검증 체계 구축**
  발화 테스트·LLM 응답 검증·타입/빌드·배포 전후 확인을 **자동 실행되는 검증 체계로 통합**하고 Playwright E2E 시나리오 5종을 **배포 파이프라인의 필수 게이트로 편입** — 사람이 판정하지 않아도 같은 기준으로 품질이 걸러지는 구조
- **LLM 응답 회귀 평가 도구 직접 제작**
  엑셀 질문 목록을 챗봇에 자동 입력해 마크다운·표·버튼이 포함된 **LLM 응답 품질을 반복 검증하는 회귀 평가 도구**를 직접 제작, 검수 결과를 **스크린샷·JSON·HTML 갤러리로 산출**해 비개발 직군도 응답 판정에 참여 가능하게 구성. 채팅 화면을 JSON 시나리오로 단계 단위 자동 조작하고 **기준 화면 대비 시각 차이 2%(기본값)를 판정 기준**으로 삼는 UI E2E 테스트 도구도 함께 제작
- **AI 활용 개발 표준 단독 설계**
  AI 생성 코드를 팀 전체가 같은 기준으로 검증·신뢰할 수 있도록 컨텍스트 관리·금지 패턴·보안 위험·검증 절차를 **프론트엔드 AI 활용 개발 표준으로 설계**, **사내 공식 문서 채택으로 연결**
- **AI 에이전트 도구 연동 환경 구성**
  **사내 문서·지식 검색용과 테스트·검증 도구 호출용 MCP 서버를 직접 개발·수정**하고 Claude Code·Codex 개발 환경에 **MCP 도구를 연동해 AI 에이전트가 사내 도구를 호출**하도록 구성, 사내 문서를 AI·챗봇이 참조하도록 연결하고 장애·오류 분석에 AI를 활용하는 절차 수립
- **공통 컴포넌트 표준화**
  Storybook 스토리 210개로 재사용 컴포넌트를 카탈로그화하고 기획자와 UI를 조기 확정해, 신규 화면 조립을 공통 컴포넌트 기반으로 전환
- **운영 확인 자동화**
  **GA4·PostHog 기반 운영 데이터 대시보드 구축**, 배포 전후 상태와 운영 지표를 비개발 직군도 직접 확인 가능하게 전환
- **데이터 기반 과제 정의**
  대시보드 지표를 근거로 개선 과제를 정의 — **진입·이탈 지표로 화면·플로우 개선 과제**를, **오류·응답 품질 지표로 품질 개선 과제**를, **사용량·활성 지표로 기능 개발 우선순위 조정**을 도출. 진입·이탈 지표로 정의한 **화면·플로우 개선 과제는 실행까지 완료**
- **학습의 조직 이식**
  외부 컨퍼런스·전문가 인사이트를 흡수해 **개발 세미나 12회**로 팀에 이식하고, 검증 기준·노하우를 **기술 문서 48건으로 자산화**해 신규 합류자도 같은 기준으로 개발 가능하게 정비

#### 성과

- **일하는 방식의 전환**
  10명 팀에서 단독 설계한 개발 표준과 검증 체계가 **전원의 개발 방식으로 정착**, E2E 필수 게이트로 담당자 부재 시에도 같은 기준의 검증·배포 유지
- **인력 효율 향상**
  반복 UI 검증을 자동 판정으로 대체해 **반복 QA 3시간 → 30분**, 반복 컴포넌트 개발을 **90분 → 15분(약 83%)**으로 단축, 검증 인력을 개발에 재투입
- **협업 리드타임 단축**
  Storybook 기반 UI 조기 확정으로 기획–개발 검증 **리드타임 2일 → 1일**
- **유지보수성 향상**
  공통 컴포넌트 카탈로그와 개발 표준·기술 문서로 코드 일관성·인수인계 기반 확보, 운영 데이터 확인 3단계 → 1단계 자동화

기술: Codex · Claude Code · MCP(Model Context Protocol) · Playwright · Storybook · Jest · ESLint · TypeScript · GA4 · PostHog · Jenkins · GitLab CI/CD

#### 주요 실행

- **LLM 서버 협업**

# 제3부. 자기소개서

## [성격의 장/단점]

**새로운 기술을 개인의 노하우로 끝내지 않고, 팀이 반복해서 사용할 수 있는 기준으로 만드는 것이 강점입니다.**

대웅제약에서 AI 코딩 에이전트 도입 후 팀원마다 활용 방식과 검증 수준이 달랐습니다. 이를 해결하기 위해 컨텍스트 관리, 금지 패턴, 보안 위험, 검증 절차를 **프론트엔드 AI 활용 개발 표준으로 설계**했고 사내 공식 문서로 채택됐습니다. 외부에서 얻은 지식도 개발 세미나 12회와 기술 문서 48건으로 축적해 **10명 팀 전원이 동일한 방식으로 개발·검증하도록 정착시켰습니다.**

반면 결과물을 충분히 검증하려는 성향 때문에 확인 작업에 시간이 많이 들 때가 있었습니다. 이를 개인의 습관이 아닌 프로세스 문제로 보고 **LLM 응답과 UI를 자동 검증하는 회귀평가 도구를 직접 제작하고 E2E 검증을 배포 게이트에 적용했습니다.** 그 결과 반복 QA 시간을 **3시간에서 30분으로 단축**했습니다.

## [직무수행 역량 및 자세]

### 1. **현업 요구를 데이터와 시스템 문제로 구조화**

AI 건강검진 챗봇 출시 후 고객사별 기능에 따라 가격을 다르게 구성해야 한다는 요구가 발생했습니다. 고객사별 화면을 별도 개발하는 대신 이를 **"하나의 서비스에서 여러 상품을 운영하는 문제"로 재정의**했습니다.

기획·운영 담당자와 기능 범위를 정리하고 Base-Theme·Config-Driven UI 구조를 도입해 **개발자가 화면을 수정하던 방식을 운영 담당자가 설정값으로 상품을 구성하는 방식으로 전환했습니다.** 이를 기반으로 신규 고객사 프론트엔드 납품 기간도 최초 구축 10주 대비 **2주로 단축**했습니다.

레거시 전환에서도 Controller·Service·SQL·DB·화면까지 테이블 참조 관계를 직접 추적해 변경 범위를 정의했습니다. **요청을 바로 구현하기보다 업무와 데이터 구조를 먼저 파악하는 것이 제 문제 해결 방식입니다.**

### 2. **LLM·Agent PoC를 실제 서비스로 전환**

AI 건강검진 챗봇에서는 기획자와 MVP를 정의하고 PoC를 거쳐 **10주 내 실서비스로 전환해 임직원 3,493명 규모로 운영했습니다.**

AI 개발자와 응답 형식, SSE 스트리밍, 오류 정책을 먼저 합의하고 중지·재시도·재생성, 상담 이력, Markdown·표·링크 렌더링과 오류 복구 구조를 구현했습니다. 또한 **Python 프롬프트와 LLM 응답 변환 로직 수정에 참여하고 RAG·VectorDB 활용 과정에 참여했습니다.**

최근에는 **사내 문서 검색과 테스트 도구를 호출하는 MCP 서버를 개발·수정하고 Codex·Claude Code와 연결해 AI 에이전트가 내부 도구를 사용하는 환경을 구성했습니다.**

**PoC의 성공 기준을 기술 시연이 아니라 실제 사용·검증·운영 가능 여부에 두고 있습니다.**

### 3. **레거시부터 API·SQL·배포까지 연결하는 실행력**

비즈36.5에서는 jQuery·Thymeleaf·Spring Boot·MySQL 기반 레거시를 분석하고 **React 화면 단위 점진 전환 구조를 설계했습니다.** 신규 기능 3건은 MySQL 데이터 모델부터 Spring Boot 서버, REST API, Web·Admin 화면까지 직접 개발했습니다.

여러 백엔드 데이터를 연결하기 위해 **Node.js 기반 데이터 집계·중계 API를 신규 구축**했고, 수동 배포는 Jenkins와 **Docker Blue-Green 무중단 배포**로 전환해 배포 시간을 **10분에서 2분으로 줄였습니다.**

삼성물산 프로젝트에서도 렌더링 생명주기 분리와 Oracle SQL 필터링·정렬 튜닝·DB 인덱싱·DTO 투영을 양단에 적용해 대용량 데이터 화면의 렌더링을 **2.5초에서 1초대**, 모바일 검색을 **5초에서 1초로 단축**했습니다.

**AI 솔루션을 기존 시스템과 데이터에 연결해 실제 운영 환경까지 가져가는 End-to-End 경험이 강점입니다.**

### 4. **새로운 기술을 조직의 업무 방식으로 정착**

AI 활용 개발 표준을 만드는 데서 끝내지 않고 **LLM 응답 회귀평가 도구, Playwright E2E 5종, 배포 검증 게이트**를 구축해 사람이 판단하던 기준을 시스템으로 옮겼습니다.

검수 결과를 스크린샷·JSON·HTML 형태로 제공해 **비개발 직군도 AI 응답 검증에 참여할 수 있도록 했고**, 세미나 12회와 기술 문서 48건을 통해 새로운 방식을 팀 전체에 확산했습니다.

한국미스미 프로젝트에서는 일본 본사 개발자와 일본어로 직접 협업하며 **6인 한국 개발팀의 Next.js 전환을 주도**했습니다.

**기술을 도입하는 것보다 현업이 사용할 수 있는 기준과 절차로 바꾸는 것이 변화관리의 핵심이라고 생각합니다.**

## [지원동기 및 목표]

**AI 기술 자체보다, AI를 이용해 실제 업무 방식을 바꾸는 일을 하고 싶어 GS글로벌 FDE에 지원했습니다.**

대웅제약에서 AI 챗봇을 PoC에서 **3,493명이 사용하는 서비스로 전환**하고, Python·RAG·VectorDB 기반 LLM 서비스 협업과 MCP 기반 AI 에이전트 환경 구성까지 경험했습니다. 또한 레거시 분석, SQL 데이터 처리, API 개발, Docker 배포를 수행하며 **AI가 실제 업무에 적용되려면 모델뿐 아니라 데이터·시스템·운영·사용자까지 함께 연결해야 한다는 점을 배웠습니다.**

GS글로벌 FDE는 사업 현장의 비효율을 찾고, 데이터와 LLM·Agent로 빠르게 검증한 뒤 현업·IT·보안 조직과 협업해 실제 업무에 정착시키는 역할입니다. 이는 제가 경험한 **문제 정의 → PoC/MVP → 시스템 연동 → 운영 → 표준화**의 과정과 직접적으로 맞닿아 있습니다.

입사 후에는 트레이딩과 물류·SCM 업무에서 **반복적인 데이터 취합, 정보 탐색, 문서 검토, 현황 조회와 판단 지연이 발생하는 지점부터 찾겠습니다.** 효과가 명확한 과제를 Python·SQL과 LLM·Agent로 빠르게 검증하고, 검증된 과제는 기존 시스템과 API로 연결해 실제 운영 가능한 서비스로 만들겠습니다.

장기적으로는 개별 PoC를 만드는 데 그치지 않고 **데이터 연동 방식, Agent 구성, 품질 검증, 배포·운영 절차를 재사용 가능한 AX 표준으로 축적하는 FDE**가 되고 싶습니다.
