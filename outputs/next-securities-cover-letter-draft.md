# 정다훈 자기소개서 (넥스트증권 · 웹 프론트엔드 개발자 (경력) 지원용)

## 운영 데이터를 다루는 관리자 시스템과 웹 성능을 직접 설계해 온 프론트엔드 개발자

저는 React·TypeScript·Next.js를 주력으로 관리자 도구·운영 시스템·고객 접점 웹을 설계하고, 웹 성능을 측정 가능한 수치로 개선해 온 6년차 프론트엔드 개발자입니다. 커머스·헬스케어·데이터 플랫폼에서 수천 행의 테이블과 역할별 데이터 조회 구조를 직접 다뤄 왔고, 운영팀 피드백을 기반으로 기능을 개선하며 서비스 안정성을 함께 관리해 온 경험이 있습니다.

넥스트증권에 지원한 이유는 두 가지입니다. 원장·환전·이체처럼 복잡한 금융 운영 데이터를 다루는 백오피스 시스템을 설계하는 역할이 제가 해 온 일의 연장선에 있고, 상품 구매 플로우를 직접 설계해 온 커머스 경험이 넥스트증권 홈페이지 개편과 B2C 제품 판매 플로우 구현에도 이어진다고 판단했습니다. 금융 도메인을 직접 다뤄 본 경험은 없지만, 복잡한 운영 데이터와 권한별 조회 구조를 설계해 온 경험이 금융 백오피스의 데이터 관리·워크플로우 처리 요건에 직결된다고 생각합니다. 그 연결 위에서 빠르게 성장하는 금융 서비스의 내부 시스템과 고객 접점 웹을 함께 끌어올리고 싶어 지원했습니다.

## 복잡한 데이터 구조와 관리자 시스템을 직접 다루다

관리자·운영 시스템에서 가장 구체적인 경험은 두 곳에서 나왔습니다.

첫 번째는 삼성물산 데이터 플랫폼입니다(소속: 내담씨앤씨 SI 프로젝트). Vue 3·ECharts·RealGrid로 수천 행의 테이블과 시계열 데이터를 렌더링하는 Web 대시보드를 개발했습니다. 전체 데이터를 한 번에 처리하면 화면 진입마다 2.5초 이상 대기가 생긴다는 문제를 확인하고, 일괄 처리 대신 테이블과 차트의 렌더링 생명주기를 분리한 뒤 Lazy Rendering을 택했습니다. 초기 진입 지연을 줄이는 것이 우선이었기 때문에 전체 정렬·집계보다 화면 진입 응답성을 먼저 확보하는 구조를 직접 설계·구현했고, 처리 시간을 2.5초에서 1초대로 개선했습니다. 운영 담당자마다 역할에 따라 다른 데이터 접근 범위가 필요했기 때문에, Spring REST API와 역할별 조회·필터·정렬 로직을 함께 설계해 권한별 데이터 표현 구조를 구성했습니다. 관리자 도구에서 역할 기반 데이터 조회가 얼마나 복잡한 요건을 만들어 내는지 이 프로젝트에서 몸으로 익혔습니다.

두 번째는 B2B 임직원 건강 플랫폼입니다. 외주 중심으로 운영되던 서비스를 내부에서 직접 개발·운영 가능한 구조로 전환하면서, 신규 건강관리 기능 3건을 MySQL 데이터 모델부터 Spring Boot 로직·REST API·Web·Admin의 입력 폼·조회 테이블 화면까지 End-to-End로 직접 개발했습니다. Jenkins CI/CD 파이프라인과 함께 WebView 및 여러 브라우저 환경에서 화면 호환성을 검증하는 기준을 수립했고, 이 경험이 넥스트증권 웹의 크로스 브라우저 대응에도 그대로 이어진다고 생각합니다. 사용자 권한·메뉴·데이터 출력 정책을 공통 기준으로 정리해 고객사별 운영 대응을 1주 내 처리할 수 있는 관리자 구조를 만들었고, 9주 안에 108개 페이지·82개 화면을 전환 완료했습니다. 넥스트증권 백오피스가 다루는 원장·환전·이체처럼 권한과 데이터 처리 흐름이 복잡한 운영 시스템에서, 이 경험이 직접적인 출발점이 될 수 있다고 판단합니다.

## 웹 성능·아키텍처와 홈페이지·B2C 플로우 개선 경험

성능 개선은 운영 시스템에 국한하지 않고 고객 접점 화면에서도 다뤄 왔습니다. 한국미스미 글로벌 B2B 커머스에서는 PHP·jQuery 기반 레거시를 Next.js·React·TypeScript 구조로 단계적으로 전환하며 페이지 접근 시간을 8초에서 2초로 단축했습니다(소속: 내담씨앤씨 SI 프로젝트). 페이지 성격에 따라 SSR과 CSR을 나누고, Lighthouse로 병목을 분석하면서 Lazy Loading·비동기 API·폰트 최적화를 적용했습니다. 상품 비교·멀티 다운로드 같은 복잡한 B2C 구매 플로우 기능은 공통 컴포넌트·Custom Hook으로 구조화해 이후 유사 기능을 빠르게 추가할 수 있는 기반을 만들었습니다.

넥스트증권 홈페이지 개편과 B2C 제품 판매 플로우 구현도 이 경험에서 이어진다고 생각합니다. 커머스에서 렌더링 전략과 사용자 플로우를 함께 잡아 온 방식을, 금융 상품 판매 흐름에 맞게 적용하면 고객 접점 웹의 성능과 전환 경험을 함께 끌어올릴 수 있습니다.

## 주도적 커뮤니케이션과 운영팀 협업

프론트엔드 개발이 끝나도 일이 끝났다고 생각하지 않습니다. AI 건강검진 챗봇을 실서비스로 고도화할 때는 API 응답 형식·스트리밍 방식·오류 정책을 AI 개발자·백엔드와 직접 조율했고, 기획·운영 조직과도 기능 노출 조건과 배포 일정을 함께 맞췄습니다. 기능 개발·고객사 배포 요청·API 정책 조율이 동시에 쌓이는 상황에서는 WBS·ETA로 우선순위를 정리해 진행했습니다.

운영팀과의 협업은 서비스를 배포한 뒤에도 이어졌습니다. 운영팀의 피드백을 기능 개선 과제로 전환하고, GA4·PostHog 기반 운영 데이터 대시보드를 만들어 운영팀이 개발팀을 거치지 않고 직접 지표를 확인할 수 있도록 했습니다. TanStack Query로 서버 응답을 캐싱해 반복 요청을 줄이고 화면 전환 속도를 높인 것도 운영 화면의 체감 응답성을 높이기 위한 판단이었습니다. 내부 사용자인 운영팀의 피드백 기반으로 기능을 빠르게 개선하는 것이 넥스트증권 백오피스 담당자가 기대하는 역할과 정확히 같다고 생각합니다. Playwright 기반 600여 건의 E2E 회귀 시나리오 자동화와 Jenkins CI/CD 파이프라인 정비로 반복 QA 시간을 3시간에서 1시간으로, 배포 리드타임을 10분에서 2분으로 줄였고, 그 결과 운영팀이 피드백을 주면 당일 반영·배포가 가능한 개발 체계를 갖췄습니다.

## 갭에 대해 솔직하게, 그리고 입사 후 기여에 대해

몇 가지는 솔직하게 말씀드려야 합니다. 금융·증권 도메인을 직접 다뤄 본 경험은 없습니다. 다만 복잡한 권한 체계, 역할별 데이터 조회, 운영 워크플로우가 복잡하게 얽히는 시스템을 설계해 온 경험은 금융 백오피스가 요구하는 구조와 가장 가까운 접점이라고 생각합니다. 도메인 지식은 코드베이스와 운영 조직의 언어를 빠르게 익히는 방식으로 채워 나가겠습니다.

스타일링 쪽에서는 Tailwind CSS·SCSS를 실무에서 써 왔고, Emotion은 직접 경험하지 않았습니다. CSS-in-JS의 구조적 특성은 이해하고 있어 실무 적응에는 큰 시간이 필요하지 않다고 판단합니다. 빌드 툴은 Next.js·Vercel 기반으로 번들 최적화를 다뤄 왔고, Vite·ESBuild·PNPM은 직접 쓴 경험이 없습니다. GitHub Actions도 마찬가지로 Jenkins·GitLab CI/CD 경험을 기반으로 익혀 나가겠습니다.

입사 후에는 백오피스의 복잡한 테이블·폼·데이터 조회 화면을 빠르게 이해하고, 운영팀 피드백을 구조적으로 반영하는 개발·배포 흐름을 만드는 일부터 시작하고 싶습니다. 내부 시스템이 안정적으로 돌아가야 고객 접점 서비스도 신뢰를 얻는다는 것을 현장에서 배웠고, 그 안정성을 프론트엔드에서 책임지는 역할을 넥스트증권에서 이어가고 싶습니다.
