# Portfolio Evaluation Rubric

Use this rubric for portfolio HTML, PDF, image assets, and project case studies.
Findings should be specific enough for a writer or designer to act on.

## Severity

- **Must fix**: likely fabrication, unsupported concrete claim, broken rendering,
  unreadable text, missing critical evidence, or a flaw that can materially harm
  recruiter trust.
- **Should fix**: weak narrative structure, vague contribution, inconsistent
  terminology, accessibility issue, or visual hierarchy problem that reduces
  persuasiveness.
- **Could improve**: polish, ordering, optional supporting evidence, or a style
  refinement that improves quality without blocking use.

## Criteria

- **Fact accuracy**: every concrete claim about role, period, metric, technology,
  product name, responsibility, and outcome is traceable to verified evidence.
- **Recruiter fit**: the opening scan makes the candidate's role, scope,
  contribution, and target positioning clear within a short read.
- **Project narrative**: each project has a clear problem, action, result, and
  candidate contribution. Avoid pure feature lists when the user's work is the
  selling point.
- **Evidence strength**: metrics are used only when approved by
  `metric-registry.md`; qualitative claims are grounded in verified facts.
- **Visual and UX quality**: layout supports scanning, printed/PDF output is
  readable, images help explain the work, and captions do not repeat empty
  claims.
- **Consistency**: product names, dates, project order, tone, and terminology
  match the reference material and remain consistent across HTML and PDF.

## Finding Format

For each finding, include:

- Severity.
- Source location: file and section or page.
- Evidence or quoted phrase under review.
- Problem.
- Recommended fix.
- Verification source or missing evidence needed.
