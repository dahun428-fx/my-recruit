책임 범위: 사용자 기능 개발, PHP·jQuery 레거시 분석, Next.js 전환, 렌더링·성능·SEO·다국어·배포·모니터링 구조 개선

[문제]

PHP·jQuery 기반 글로벌 B2B 쇼핑몰은 화면 간 결합도가 높아 기능 확장과 유지보수가 어려웠습니다. 긴 초기 접근 시간과
단일 렌더링 방식으로 인해 성능과 검색 노출을 함께 최적화하기 어려웠으며, 국가별 사용자 환경을 지원하면서 서비스
구조를 단계적으로 현대화해야 했습니다.

[주요 실행]

- PHP·jQuery 레거시를 분석해 Next.js·TypeScript 기반 컴포넌트 구조로 전환하고, 페이지 특성에 따라 SSR·CSR 렌더링 전략
분리
- 상품 비교·멀티다운로드 등 복잡한 기능을 공통 컴포넌트와 Custom Hook으로 구조화하고 Redux·브라우저 저장소를 통
해 사용자 상태의 일관성 확보
- Lighthouse 기반 병목 분석과 Lazy Loading·비동기 API·리소스 최적화를 수행하고 SEO·영중일 다국어 구조 적용
- Vercel 배포 자동화, Datadog 오류 추적 및 Google Analytics·Adobe Analytics 기반 사용자 분석 체계 구축

[성과]

- 유지보수·성능 개선 프로젝트에서 페이지 접근 시간을 8초 → 2초로 단축
- Next.js 전환 프로젝트에서 기존 PHP 서비스 대비 평균 로딩 속도 약 50% 개선
- 인터랙션 기능 개선 이후 사용자 체류 시간 32% 증가
- 사용자 화면 개발에서 시작해 글로벌 서비스의 아키텍처·성능·다국어·배포·모니터링까지 책임 범위 확장

기술: Next.js, React, TypeScript, JavaScript, Redux, RxJS, i18next, PHP, jQuery, Twig, Vercel, Datadog, Google Lighthouse, Google

자기소개서

      AI 서비스를 실사용 가능한 제품으로 전환하는 개발자

        저는 AI 서비스를 PoC에서 실사용 가능한 제품으로 전환해 온 6년차 프론트엔드 중심 Product Engineer입니다. React·TypeScript 기반 아키텍처 설계에 강
        점이 있으며, 화면 구현을 넘어 응답 속도, 오류 대응, 데이터 흐름, 운영 검증과 배포 안정성까지 제품 완성도에 필요한 영역을 함께 설계해왔습니다.
        대웅 AI추진팀에서는 AI 건강검진 챗봇의 실서비스 전환을 담당했습니다. 초기 챗봇은 LLM 답변이 모두 생성된 후 화면에 출력돼 체감 대기 시간이 길
었고, Markdown·표·링크·긴 답변 등 비정형 데이터를 안정적으로 처리할 구조도 부족했습니다.

이를 해결하기 위해 AI 개발자와 API 응답 형식 및 오류 정책을 조율하고, SSE 기반 실시간 렌더링을 적용했습니다. 답변 중지·재시도·오류 상태 처리와
Markdown 전용 렌더링 계층을 구축했으며, XSS 필터링과 LLM 오류 가드레일을 적용해 예측하기 어려운 응답도 안전하게 출력되도록 했습니다. 그 결
과 3,493명을 대상으로 PoC를 수행하고, 답변 출력 시간을 10초에서 4초로 단축했습니다. 핵심 발화 400건에 대한 회귀 검증에서는 답변 화면 정상 출
력률 100%를 달성했습니다.

확장 가능한 프론트엔드 구조를 설계하다

저는 프론트엔드 개발자의 역할이 화면 구현에 그치지 않고, 서비스가 성장해도 안정적으로 확장될 수 있는 제품 구조를 설계하는 데 있다고 생각합니
다.

B2B SaaS에서는 고객사마다 CI, 문구, 화면 흐름과 기능 노출 조건이 달랐습니다. 고객사별로 서비스를 개별 개발하면 구축 기간과 품질 편차가 커질 수
있다고 판단했습니다. 이에 공통 화면과 컴포넌트, 테마, 기능 노출 조건을 Base-Theme과 Config-Driven UI 구조로 분리했습니다. 이를 통해 신규 AI 챗봇
구축 기간을 기존 10주에서 약 2주 수준으로 단축할 수 있는 기반을 마련했습니다.

사용자 체감 성능을 개선하기 위해서는 React Query 캐싱, 코드 스플리팅, 이미지 최적화와 렌더링 전략 분리를 적용했습니다. 글로벌 B2B 커머스 프로
젝트에서는 PHP·jQuery 기반 레거시 서비스를 Next.js·TypeScript로 전환하고, 페이지 특성에 따라 SSR과 CSR을 구분해 평균 로딩 속도를 약 50% 개선했
습니다.

제품 운영에 필요한 영역까지 책임지다

프론트엔드에 강점을 두되, 제품 운영에 필요한 백엔드·데이터·배포 흐름까지 이해하고 직접 개선해왔습니다. 대표적으로 외주 중심으로 운영되던 B2B
임직원 건강 플랫폼을 내부에서 개발하고 운영할 수 있는 구조로 전환했습니다.

기존 소스와 DB 스키마를 분석해 화면 요청부터 Controller·Service·Query·DB 조회·화면 출력까지 이어지는 데이터 흐름과 기능별 의존 관계를 정리했습니
다. 이후 신규 건강관리 기능 3건의 MySQL 데이터 모델과 Spring Boot API, Web·Admin 화면을 End-to-End로 개발했습니다. 기존 운영에 영향을 주지 않
도록 jQuery·Thymeleaf와 React가 화면 단위로 공존하는 점진적 전환 구조를 적용하고, WebView 앱 대응과 Jenkins 기반 CI/CD 파이프라인도 구축했습니
다.

그 결과 기존 서비스를 중단하지 않고 Web·Admin·App 영역의 108개 페이지와 82개 주요 화면 규모의 전환을 9주 안에 수행했습니다. 또한 외주에 의존
하던 기능 변경과 배포를 DB·백엔드·Web·Admin·App 전반에서 내부 대응할 수 있게 했습니다.

AI를 실무 생산성으로 연결하다

최근에는 AI Coding Agent가 코드 생성에 그치지 않고, 프로젝트의 맥락을 이해해 구현부터 검증까지 수행할 수 있는 환경을 설계하고 있습니다. 저는
이를 하네스 엔지니어링, 즉 Agent가 안정적으로 작업하도록 개발 기준, 프로젝트 맥락, 도구, 테스트와 완료 조건을 구조화하는 일이라고 정의합니다.

AGENTS.md에는 폴더 구조, 네이밍, 상태 관리, 보안 기준과 테스트 명령을 정의했습니다. 반복 업무는 SKILL.md로 표준화하고, Figma·Storybook을 통해
디자인과 기존 컴포넌트의 맥락을 제공했습니다. 여기에 Playwright 기반 E2E 테스트와 시각 회귀 검증, CI/CD를 연결해 Agent가 생성한 결과를 직접 검
증하고 수정하는 반복 구조를 구축했습니다.

그 결과 반복 컴포넌트의 개발·검증 시간을 90분에서 15분으로 단축했습니다. 또한 600여 건의 E2E 회귀 시나리오를 자동화해 반복 QA 시간을 3시간에
서 1시간으로 줄였습니다.

저는 AI 개발 생산성이 모델의 성능만으로 결정되지 않는다고 생각합니다. Agent가 참고할 맥락과 재사용 가능한 작업 절차, 검증 도구와 명확한 완료
조건이 함께 설계돼야 실무에 안정적으로 활용할 수 있습니다. 앞으로도 프론트엔드 아키텍처와 하네스 엔지니어링을 결합해 개발팀과 AI Agent가 더
빠르고 일관되게 제품을 만들 수 있는 환경을 구축하겠습니다.
