# Base Resume (base-theme 마스터 이력서) — **표준 정본**

이 문서는 소유자의 **표준 이력서**다. 새 회사 지원 = 이 문서에서
**편집**(재조립 아님). 2026-07-24~25 grill-me 세션에서 전 섹션을 확정했고,
2026-07-27 세션에서 **FE 지원자 10명 벤치마크 대조**로 전면 재작성했다.
같은 날 적대 검증·`reviewer` 사실 검증을 돌렸고, **지적사항은 소유자 판단으로
대부분 기각하고 소유자 확정 문면을 정본으로 유지한다**(아래 메모 참조).

**렌더 정본**: `outputs/base-resume.html` + `outputs/base-resume.css`가
이 문서의 시각 템플릿이자 **다른 회사 이력서의 캐논 구현**이다(DESIGN.md의
Reference implementation 포인터가 이 두 파일을 가리킨다). 새 변형은 이
구조·CSS를 재사용해 렌더한다.
2026-07-27 재작성판으로 재렌더 완료 — 9페이지, 오버플로우 검증 통과.
신설 클래스: `.core-chips`·`.core-evidence`(핵심 성과 칩+근거 3단),
`.stack-paren`(경력 명세형 스택 괄호), `.skills-table`(기술 10행 2열 표).

## 새 JD로 이력서 쓰는 법 (edit-from-base)

1. **JD 수집** — `tailor`가 `target-companies.md`에 엔트리 생성(수집일·출처).
   Screen profile / Role preset 태그 확정.
2. **base 복제 → 타겟 편집** — 이 문서를 `outputs/<slug>-full-resume-draft.md`로
   복제하고, 아래 **편집 규칙의 "가변" 레버만** 움직여 JD에 맞춘다. "불변"은
   건드리지 않는다. JD 요건 중 base에 근거 없는 갭은 갭 인터뷰 →
   `experience-bank.md` 적재 후 반영(무근거 요건을 조용히 빼지 않는다).
3. **크리틱 → 점수 게이트** — `reviewer`+`ats` → 수정 → `recruiter-screen`+
   `tech-screen`(회사 Screen profile로 포지셔닝) 통과(P-01). 새 섹션·항목
   초안은 확정 전 3자 자문 리뷰 기본(P-03).
4. **렌더** — `designer`가 `base-resume.html/css` 구조를 재사용해
   `outputs/<slug>-full-resume.{html,css}` 생성, 매 렌더 자동 높이
   오버플로우 검증.
5. **복제 시 제거 체크리스트** — 상단 메타 4섹션(문서 아키텍처·편집 규칙·
   상태·메모), 「상태」의 `[확인 필요]` 목록.
6. **승격 루프** — 확정된 새 문장은 base-resume.md·`canonical-lines.md`
   반영 후보로, 브리프 예외는 `target-companies.md`에 기록 제안(승인제).

## 문서 아키텍처 (2026-07-27 확정) — 계층별 임무 분담

각 섹션이 서로 다른 일을 한다. **같은 사실을 두 계층에서 반복하지 않는 것**이

| --- | --- | --- | --- |

| 경력기술서 | "서사와 근거" | 문제 → 판단 → 실행 → 성과 전량 | — |
| 기술 | "도구 인벤토리" | 카테고리별 도구 나열만 | 경험 근거 서술(경력기술서 소관) |

**의도된 예외 (2026-07-27 소유자 결정 — "위반"으로 판정해 되돌리지 말 것)**

  중복이지만 **의도적으로 유지**한다. 경력은 경력기술서 진입 직전의 흥미
  유발 구간이므로 수치가 여기 있어야 한다는 소유자 판단.
- 스택이 요약·경력·기술 표에 3중 노출되는 것도 **유지**한다. 요약은 산문
  인라인, 경력은 프로젝트별 귀속, 기술은 전체 인벤토리로 기능이 다르다.

**수치 선별 기준(2026-07-27 확립)**: 수치는 많고 적음이 아니라 **독자가 그
숫자로 규모를 스스로 그릴 수 있는가**로 고른다. `3,493명`·`108개 페이지`는
그려지고, `REST API 31종`·`응답 모델 33종`은 정확하지만 그려지지 않는다.
그려지지 않는 수치는 읽는 부담만 주므로 뺀다.
