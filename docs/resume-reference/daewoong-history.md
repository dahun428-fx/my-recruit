# 대웅제약 History (월별 자가 피드백 · 본인 「잘한 점」 원장)

소유자가 대웅제약 AI추진팀 재직 중 **매월 직접 작성한** 월별피드백의
`구분: 본인` × `잘한 점` 칼럼만 추출한 원장이다. 2025-07 ~ 2026-07,
13개월 전량 + 작성 메모 시트 1건 + 2026-08 1개월(요약 형태, 아래 참조).

**이 문서의 임무**: 대웅 1년의 실제 활동을 월 단위로 보존해, 이력서·자기소개서·
면접 준비에서 필요한 소재를 **꺼내 쓰는 진입점**이 되는 것. 사실 정본은
`experience-bank.md`, 지표 정본은 `metric-registry.md`이며 이 파일은
**원문 보존 계층**이다.

- 출처: `sources/월별피드백_정다훈.xlsx` (2026-07-29 소유자 제공, 원본은
  `.gitignore` 대상; 2025-07~2026-07 13개월분). 2026-08분은 갱신본
  `월별피드백_정다훈 (7).xlsx`에서 나왔으나 이 프로젝트 `sources/`로 아직
  임포트되지 않았다 — 상세는 `source-materials.md`와 아래 2026-08 절의
  2026-08은 원문 전사 완료(2026-09-09).
- 원문 전문: 이 파일 하단 「월별 원문」 절이 정본이다(별도 extracted 사본 없음).
- 추출 범위: `구분 = 본인` 행의 `잘한 점` 칼럼만. `부족한 점 및 보완계획`,
  상사 평가 행은 **미추출**(소유자 지시).

## 사용 규칙 — 읽기 전에

1. **이 문서의 수치는 아직 검증 상태가 아니다.** 소유자 자가 평가 원문이므로
   `metric-registry.md`에 등재되기 전에는 지원 문서에 그대로 쓰지 않는다.
   쓰려면 registry에 먼저 올리고 스코프를 확정한다(C-05).
2. **"기대" 어형에 주의한다.** 원문에는 `+10% 기대`, `20% 단축 기대`,
   `향상 기대`처럼 **실현되지 않은 예상치**가 섞여 있다. 실현 성과와 구분해
   서술한다(T-03). 이 원장에서 실측/예상을 구분하지 않고 그대로 보존했으므로,
   꺼내 쓸 때 원문의 어미를 반드시 확인한다.
3. **같은 사건의 중복 계상 금지.** 배포 시간 단축, 테스트 커버리지처럼
   대상이 다른 유사 수치가 여러 달에 흩어져 있다. 아래 「충돌·정합 확인 필요」를
   먼저 본다.
4. 이 파일은 편집 대상이 아니라 **적재 대상**이다. 새 월 피드백이 생기면 같은
   방식으로 추가하고, 여기서 확정된 사실은 `experience-bank.md`로 승격한다.

## 충돌·정합 확인 필요

꺼내 쓰기 전에 반드시 짚어야 할 것들이다.

1. **응답/진입 속도 수치가 3계통으로 얽혀 있다.**
   `metric-registry.md`에는 `AI 답변 출력 10초 → 4초`(confirmed)와
   `초기 진입 30초 → 6초`(confirmed)가 있다. 그런데 이 원장에는
   2025-07 "챗봇 **출력** 속도 최대 30초 → 6초", 2026-01 "첫 **진입** 로딩
   6초 → 2초", 2026-03 "SSE 전환으로 체감 응답 10초 → 4초", 2026-04
   "초기 화면 로딩 2초 → 1초"가 각각 있다. **registry의 "진입 30초→6초"가
   실제로는 "출력 30초→6초"일 가능성**이 있고, 진입은 6→2→1초로 이어지는
   별도 체인으로 보인다. 소유자 확인 필요.

2. **배포 시간 단축이 4건, 대상이 전부 다르다.**
   비즈케어 Jenkins 10분 → 2분(2025-11, registry 등재), 비즈36.5 운영 서버
   10분 → 1분(2026-01), AI코치 배포 5분 → 1분(2026-04), RN 빌드 5분 →
   1분(2026-06). 하나로 뭉뚱그리면 과장이 된다.

3. **테스트 커버리지 98%의 스코프가 풀렸다.** registry에서
   `테스트 커버리지 98% 수준`은 `needs_scope`로 사용 보류 중인데, 2025-11
   원문이 **"핵심 비즈니스 로직(API·템플릿) 64% → 98%"** 로 스코프를
   특정하고 있다. 다만 2026-06에는 **"test coverage 54% → 84%"** 가 있어
   측정 대상이 다르다. 둘을 구분해 registry를 갱신할 수 있다.

4. **반복 QA 3시간 → 30분**(registry confirmed)은 이 원장에 없다. 대신
   2026-07의 "내부 QA 30분 → 10분", 2026-05의 "E2E 30분 → 5분"이 있다.
   3시간→30분의 원출처는 여전히 종합평가 문서뿐이다.

5. **400여 건 발화 검증**은 2026-04 원문이 "Markdown·표 렌더링 정상률
   100%, 출력 오류 0건"으로 registry의 "답변 화면 정상 출력률 100%"와
   정합한다. 스코프 표기는 registry 표현을 따른다.

6. **Lighthouse 91점**은 2025-10 측정이며 원문에 "상위 10%"가 함께 있다.
   registry의 `source_stated` 상태를 보강할 근거다.

# 부록 C. 세 자료 간 충돌 — 사용 전 반드시 해소

`월별피드백`(2025-07~2026-07) · `연종합평가2025`(2025-12) ·
`직무급 지원서`(2026-03) 셋의 작성 시점과 목적이 달라 같은 사건의 수치가
어긋난다. **어느 하나를 고르는 게 아니라, 소유자가 어느 값이 맞는지 확정해야
한다.**

1. **AI코치 사용자 수 — 3,493명 vs 약 5,000명.** 연종합평가(2025-12)는
   "2차 POC 사용자 3,493명", 직무급 지원서(2026-03)는 "약 5,000여 명(목표
   3,000명 대비 167%)". 3개월 시차로 증가한 것일 가능성이 높지만, 현재
   `metric-registry.md`는 3,493명을 **활성 사용자**로 등재하고 있어 정의가
   엇갈린다. base-resume·포트폴리오 전반이 3,493명을 쓰고 있으므로 변경 시
   파급이 크다.

2. **매출 — 4.66억(93.2%) vs 4.86억(97.2%).** 둘 다 목표 5억 기준.
   연말 확정치와 이후 정산치의 차이로 보이나 확인 필요. registry는
   4.66억을 `needs_scope`로 보류 중.

3. **평균 응답 1.2s → 0.7s의 원인 귀속.** 연종합평가는 HTTP/2 전환 성과로,
   월별피드백 2025-09은 대화 이력 API 최적화 성과로 기재. 같은 수치를 두 개의
   서로 다른 개입에 귀속하면 면접에서 무너진다.

4. **응답/진입 속도 3계통.** 30초→6초(원문 "초기 진입 응답 속도" /
   직무급 문서는 "AI 응답 시간"), 6초→2초(2026-01 첫 진입 로딩),
   10초→4초(2026-03 SSE 전환), 2초→1초(2026-04 초기 화면 로딩).
   registry의 `초기 진입 30초→6초`와 `AI 답변 출력 10초→4초` 라벨이
   실제와 맞는지 재확인 필요.

5. **비즈36.5 전면 개편 기간 — 8주 vs 9주.** 직무급 지원서 8주,
   월별피드백 2026-01 및 base-resume 9주(108페이지·82화면).

6. **문서 건수 — 48건 vs 130건.** 48건은 개발 세미나 기술 문서,
   130건은 요구사항 정의서·기능명세서·테스트·온보딩 문서를 포함한
   조직자산 총계로 보인다. 범주가 다르면 둘 다 유효하나, 한 문서에서
   섞어 쓰면 안 된다.

7. ⚠⚠ **"연간 프론트엔드 쉐어드 비용 절감 약 5,700만 원"**은
   `metric-registry.md`가 `sensitive`로 분류한 **연봉 5,700만원과 같은
   숫자**다. 쉐어드 인력 비용을 본인 인건비 기준으로 산정했을 가능성이 크며,
   이 수치를 외부 지원 문서에 쓰면 **본인 연봉을 사실상 공개하는 결과**가
   된다. 소유자 확인 전까지 외부 문서 사용 금지.

8. **"1인당 매출 약 2.4억 원"**은 조직 매출을 인원으로 나눈 값이므로
   개인 성과로 제시하면 팀 성과 포장으로 읽힌다(EXP-06의 팀 KR 가드레일과
   동일 리스크).
