## 새 AI 직무 JD로 이력서 쓰는 법 (edit-from-base)

1. **JD 수집** — `tailor`가 `target-companies.md`에 엔트리 생성(수집일·출처).
   Role preset `ai-product`/`ax-harness` 또는 Screen profile `AI-Product` 확정.
2. **base 복제 → 타겟 편집** — 이 문서를 `outputs/<slug>-full-resume-draft.md`로
   복제하고 아래 **편집 규칙의 "가변" 레버만** 움직인다. JD 요건 중 근거 없는
   갭은 갭 인터뷰 → `experience-bank.md` 적재 후 반영(조용히 빼지 않는다).
3. **크리틱 → 점수 게이트** — `reviewer`+`ats` → 수정 → `recruiter-screen`+
   **`ai-tech-screen`**(고정 AI 루브릭; Screen profile은 recruiter-screen에만) 통과(P-01). 새 섹션·항목
   초안은 확정 전 3자 자문 리뷰 기본(P-03).
4. **렌더** — `designer`가 `base-resume.html/css` 구조를 재사용해
   `outputs/<slug>-full-resume.{html,css}` 생성, 매 렌더 자동 높이 오버플로우 검증.
5. **복제 시 제거 체크리스트** — 상단 메타 4섹션(문서 아키텍처·편집 규칙·
   상태·메모), 「상태」의 미확인 목록.
6. **승격 루프** — 확정된 새 문장은 이 문서·`canonical-lines.md`(`ai-product`·
   `ax` 태그) 반영 후보로 제안(승인제).

## 문서 아키텍처 — 계층별 임무 분담 (`base-resume.md`와 동일 원칙)

같은 사실을 두 계층에서 반복하지 않는다(F-08).

| 계층 | 임무 | 담는 것 | 담지 않는 것 |
| --- | --- | --- | --- |
| 요약 | "누구인가" | AI 서비스 개발 정체성·기술 범위·궤적 | 수치, 회사·프로젝트 나열 |
| 핵심 성과 | "자랑" | 칩(라벨) + 근거 1줄의 시그니처 수치 | 초·분 단위 프로세스 개선치 |
| 경력 | "흥미 유발 명세" | 조직 규모·담당 범위·스택 인벤토리 | 산문 서사 |
| 경력기술서 | "서사와 근거" | 문제 → 판단 → 실행 → 성과 전량 | — |
| 기술 | "도구 인벤토리" | 카테고리별 도구 나열만 | 경험 근거 서술 |

**의도된 예외 ("위반"으로 판정해 되돌리지 말 것)**

- `base-resume.md`의 의도된 예외(경력 라인 성능 수치·스택 3중 노출)를 그대로
  승계한다.
- **시스템 규모 수치**(서브에이전트 18개·8카테고리·평가 240건)는 "팀이 구축한
  시스템 규모"로만 쓴다. 핵심 성과 ①과 경력기술서 1번에 같은 수치가 있는 것은
  1페이지 ↔ 경력기술서 예외(독자 도달 시점 차이)로 유지한다.
- **기여 경계 문구**("팀 단위로 개발한 … 설계·구현에 참여하며 직접 코드를
  작성")는 C-01의 축소 한정어가 아니라 은행 최신 가드가 허용한 귀속 문법이다
  (EXP-01·v2 MAS 「[갱신 2026-11-12]」). 빼면 단독 구축으로 읽혀 과대 귀속이
  되고, 줄이면 실제 코드 작성이 과소 표기된다 — 문구를 바꾸지 말 것.
